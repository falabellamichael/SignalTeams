# SignalTeams 📡

Buzz's feed + Discord's channels, remixed into one smoother app for you and
your friends to **share agents** — prompts, personas, whole workers.

![stack](https://img.shields.io/badge/stack-FastAPI%20%2B%20React%2FVite%20%2B%20SQLite-4da3ff)

## Run it

```
start.bat                  # dev: backend (:8075) + vite (:5175)
start-lan.bat              # LAN: builds frontend, serves ALL on :8075 — friends hit http://<your-ip>:8075
```

or manually:

```
backend\.venv\Scripts\python.exe backend\run.py   # API on :8075
cd frontend && npm run dev                        # UI on :5175
```

Open http://localhost:5175 — demo logins `mike` / `nova` / `juno`, password `password`.
Re-seed any time: `backend\.venv\Scripts\python.exe backend\seed.py`.

## What's inside

- **The Buzz** — activity feed: who published, starred, benched, joined (the Buzz part)
- **Servers & channels** — Discord-style rail + `#` text channels and `✦` agent channels
- **Agent Library** — publish, search, tag-filter, sort, star, bench, fork, review, export/import JSON
- **📦 Agent packs** — bundle agents into a named toolkit; friends bench it all in one click, ⑂ fork the whole bundle into their library (with attribution), and packs drop into chat as embeds
- **Share-to-channel** — agent cards drop into chat as rich embeds
- **⚡ Try it** — run any agent against your local models (Ollama / LM Studio), streaming replies
- **🔌 Any endpoint, any harness** — Settings → Custom LLM endpoint plugs any OpenAI-compatible API (OpenRouter, Groq, vLLM, llama.cpp, OpenAI itself) or a raw **webhook harness** (POST `{system_prompt, messages, model, temperature}` → `{reply}`) into your account. Your channel summons, agent DMs, and Try tab try it first with automatic fallback to local providers; the TryTab model select lists `custom:` models live from the endpoint's `/v1/models`. `PUT /api/me/llm` stores url/kind/model (key is write-only, `has_key` on read), `POST /api/me/llm/test` probes connectivity; streaming uses real SSE parsing for OpenAI and buffered single-token replies for webhooks
- **● Endpoint health dot** — the Settings → Custom LLM endpoint label shows a green/red ● after a Test click so you can tell at a glance whether your harness is reachable
- **🔗 Grounded agents** — a Context URL on any agent gets fetched before every reply (summon, Try, and stream paths alike): `agents.context_url` → GET with a 5s timeout and 2KB cap, body injected into the system prompt as `Live context`. Turns agents into live-data bots — scoreboards, metrics, status pages — all inside the "any harness" theme since the URL is just another endpoint. Graceful empty on timeout/404; a 🔗 grounded chip shows on the card; persists through export/import/fork
- **🗝 Custom endpoint headers** — the Settings LLM section takes an extra-headers JSON (`users.llm_headers`): merged into every custom-endpoint request — webhook POSTs, OpenAI chat + SSE streams, and `/v1/models` discovery — so harnesses needing `X-Api-Key` or org headers work. Write-only like the key (`has_headers` on read, `{}` clears, validated JSON or 400)
- **🪝 Webhook shape normalizer** — the webhook-harness parser now accepts ~any reply shape: `{reply|content|text|response|output|result|answer}`, `{message}` (string or `{content}`), OpenAI-ish `{choices:[{message|text|delta}]}`, nested `{data:{…}}`, `{messages:[…]}` last-item, a bare list, or a raw string body — both the one-shot and stream paths share `_wh_text`
- **▌ Streaming agent replies** — channel summons now type live: the bot's bubble seeds with a ▌ cursor, `chat_stream` tokens flush via `message_updated` edits every ~0.6s (threaded pump → queue → async drain), and the cursor clears into the final text. Works across Ollama, LM Studio, custom OpenAI endpoints, and webhooks — any harness that streams, streams visibly; buffered ones just appear at once
- **🪝 Incoming channel webhooks** — SignalTeams *is* a harness too: channel ⚙ → Webhooks mints `/api/hooks/{token}` URLs (10 per channel, owner-managed: create/rename/rotate/delete, uses + last-used tracked). External services POST Discord-style `{content, username, embeds, allowed_mentions}`, Slack-style `{text}`, a form `payload`, or a bare body — messages land in-channel from a `hook:<id>` bot user with a **BOT** pill (plus `via <hook>` when `username` overrides the name). Mentions stay opt-in through `allowed_mentions` (`users`/`roles`/`everyone`), leftover `@names` summon agents under the hook creator's visibility, and each hook is rate-capped at 8 posts/10s. `GET /api/hooks/{token}` is a token-gated info probe
- **🧠 Per-server LLM endpoint** — the owner can point a whole server at one engine (OpenAI-compatible or webhook): `servers.llm_*` set in Server Settings → Server LLM endpoint with its own Test button and health dot. Summons in that server use the shared engine first, falling back to the asker's own endpoint then local providers. The key is write-only (`has_llm_key` on reads), stripped from every server serialization, and the test route is owner-gated
- **🔌 Crew-wide env endpoint** — `AGENTHIVE_LLM_URL`/`_KEY`/`_MODEL`/`_KIND` set a host-level custom endpoint that any member without their own config falls back to (same OpenAI/webhook plumbing — run the whole crew on one OpenRouter key or vLLM box with zero per-user setup)
- **⚡ Lurking agents** — agent-channel residents get a `⚡ lurks` toggle: lurkers auto-reply to human messages without an @-summon — one lurker per message, ~60s shared cooldown per agent+channel, skipped when someone @-summons or the message is `@silent`/a thread reply/from a bot. Lurk replies are ambient (reply-quote only, no @prefix, no mention buzz); the sidebar shows ⚡ on lurker channels.
- **📅 Scheduled agent digests** — channel ⚙ → Agent digest picks an agent (or the plain Digest bot) + interval (15 min → weekly); a 30s poller fires `PUT /api/channels/{cid}/digest` jobs, recaps that interval's messages as the agent's own bot voice (personality from its system prompt), and posts a `📅 digest` in-channel. Quiet intervals (<4 messages) and offline-LLM runs are skipped silently — no spam. Endpoint chain: agent's own connection → server LLM → creator's endpoint. Owner-only set/remove, logged to the audit feed.
- **🧭 Provider-prefixed agent models** — an agent's Model field accepts `ollama:llama3`, `lmstudio:model`, or `custom:gpt-4o` and routes to exactly that provider (`_split_model` parses the prefix in summons + both Try endpoints). Bare names still chain across all providers; explicit Try-tab selections always win; unknown names fall back to the provider's first model instead of erroring
- **⇅ Channel reorder** — owners hover a channel → `↑`/`↓` swaps it with the neighbor in its section; `POST /api/servers/{sid}/channels/order` takes the full id list (400 on partial/foreign ids), broadcasts `server_changed` to every member, and the sidebar optimistically re-renders with rollback on failure
- **🌡 Per-agent temperature** — `agents.temperature` (nullable → 0.7 default, clamped 0–2 in `llm._temp`) flows into channel summons, agent DMs, and both Try endpoints. Publish/edit modal has a "Creativity" slider (0 precise → 2 wild); non-default values show a `🌡` chip on cards + the About tab, ride along on export/import/fork/history snapshots + diffs, and appear in `/api/me/export`
- **DMs** — one-on-one channels with typing indicators + presence
- **⌨ Sidebar typing** — typing `WS` events are lifted into an app-level map, so DM rows show a pulsing italic "Nova typing…" line under the conversation even when you're looking at another channel (agents included — "LoreKeeper typing…"); entries self-expire after 7s and clear instantly on send
- **Profile popovers** — click any member row or message avatar → card with bio, status, their published agents (click-through to agent modals), Message/Add-friend actions. Clicking an agent's bot avatar jumps straight to its agent card

The rail + server header render the uploaded image in place of the emoji — changes broadcast over `_server_changed` so every member's rail updates live

- **⏰ Reminders in the Inbox** — pending `/remind` items render in the 📥 Inbox as a "your reminders" section: text, `fires in Xm` countdown (`timeUntil`), `#channel`, and a ✕ cancel that hits `DELETE /api/reminders/{id}`. `GET /api/reminders` now joins the channel name

- **Jump-to-message** — every search result (global or per-channel) and pinned message click scrolls to the exact message and pulses it honey
- **🔍 Search filters** — Discord-style tokens work in both search boxes: `from:me`/`from:name`, `in:channel` (global), `mentions:me`, `has:link` `has:attachment` `has:image` `has:embed` `has:poll` `has:reaction`, `pinned:true`/`is:pinned`, and `before:`/`after:`/`during:YYYY-MM-DD`. Filters AND together and combine with free text (`from:nova deploy`); a filter-only query runs with no text at all. Hint lines in both UIs list the syntax.

- **🔗 Agent deep-links** — a 🔗 Link button in every agent modal copies `{origin}/#/agent/{id}`: pasting it opens the agent card directly on load (visibility-gated like the API — outsiders get nothing). Joins the message permalink and invite-link hash routers

- **🛡 Automod** — Server Settings → Automod: blocked-word list, block-all-links with an allowed-domain list, mostly-caps (10+ chars, ≥70% uppercase), and a max-mentions cap (1–25). Rules live in `servers.automod` (normalized server-side), enforced on human posts pre-insert with a `400 "Automod blocked it — <reason>"` — the owner and bots/webhooks are exempt, and every block lands in the audit log (`automod.block`) so mods can see what got caught.
- **🚪 Join/leave system messages** — invite joins and leaves post a centered `system` line ("🚪 X joined the server" / "👋 X left the server") into the server's first text/forum channel (`messages.system` flag), broadcast over WS like a normal message but rendered as a dim centered row — never grouped with author streaks and invisible to search-as-content
- **📅 Scheduled events** — sidebar Events row (📅 with an upcoming count) opens a modal where any member can schedule a server event (name, description, start time, announce channel), edit it (creator/owner), cancel it, or star it as **Interested**. A 20s `event_loop` flips due events to `live`, posts a 📅 bot announcement into the channel, buzzes interested members (`emit_buzz` "event" entries), and pushes a WS `event` payload so the modal + badge update live. 25 upcoming-event cap per server; `event.create`/`event.cancel` land in the audit log
- **🔔 Keyword notifications** — Settings → Keyword notifications takes a comma-separated highlight list (`users.keywords`, max 25×40 chars, lowercased). `post_message` scans every post for channel members' words with whole-word matching (phrases like "spaced out" work, `deployer` ≠ `deploy`) and pings them: a `keyword` buzz entry with the matched word + excerpt, the @-mention badge, and the WS buzz push — `@silent` suppresses, self-posts and blocked users never fire, and an already-@mentioned member isn't double-pinged
- **🔨 Bans & timeouts** — owner-side moderation beyond kick: `POST /api/servers/{sid}/bans/{uid}` removes a member *and* blocks rejoin (invite-code joins 403 "You're banned from this server") until `DELETE .../bans/{uid}`; `POST .../members/{uid}/timeout {minutes}` sets `server_members.timeout_until`, and `post_message` 403s ("You're timed out — back in Nmin") while it's live. Member rows show a ⏱ badge while timed out, the settings modal gets 🚫/⏱ action buttons and a collapsible **Bans** list with unban, and `member.ban`/`member.unban`/`member.timeout` are audit-logged
- **📜 Audit log** — Server Settings → Audit log records who did what: channel/role/emoji/webhook create+update+delete, kicks, joins-by-knock, nickname changes, role assigns, invite rotations, ownership transfers, server edits (never the LLM key), and message deletes. `GET /api/servers/{sid}/audit?before=` pages newest-first, owner-only, capped at 500 rows per server with the tail pruned on each write

- **Channel categories** — optional `category` on text channels (create/edit modals) groups them under collapsible `▾ NAME` headers in the sidebar, first-appearance order. Uncategorized channels stay under `TEXT CHANNELS`; agent channels keep their own section.

Owner-gated create/delete/assign; `_server_changed` repaints everyone's lists live.
- **🔒 Role-gated channels** — any channel can be limited to a role in the channel edit modal ("Visible to"). Members without it see a 🔒 row and a "You need the X role" notice instead of history or a composer; reads, sends, WS fan-out, badges, mentions, and search all enforce server-side via one choke-point check. - **🏷 @role mentions** — typing `@mods` pings every member holding that role: red `@n` badges, inbox rows, buzz events, desktop notifications — all filtered through block and muted/mention-only channel rules. Votes ride the existing reaction system (`1️⃣`–`9️⃣`), so counts update in real time for everyone and click-again un-votes; multi-option voting works for ranked-choice. - **✓✓ DM read receipts** — `channel_members.last_read` stamps via `POST /api/channels/{cid}/read` on open and on every incoming message while you're in a DM; a `read` WS event updates the other side live. Mention-only hides plain unread badges but keeps red `@n` ping badges *and* desktop notifications for actual pings (muted kills all three). - **👋 Welcome checklist** — brand-new accounts get a honey card on the home surfaces: `○ Create or join a crew → opens the team modal`, `○ Add a friend → Friends view`, `○ Bench your first agent → Library`, plus an `@agentname` tip. - **🧵 Agents in threads** — summoning `@agent` inside a thread keeps the whole exchange there: the reply carries `thread_root` (renders in the panel, bumps the root's reply chip, never leaks to channel root), agent→agent chains inherit the thread, and history context scopes to the thread's own messages + root instead of the whole channel.

Their messages collapse to `🚫 name — blocked message` rows anywhere they appear (click to reveal); your own view only. Controls live on the profile card (`🚫 Block`/`🔓 Unblock`) and a `Blocked` tab in Friends manages unblocks.

## Auth providers

Settings → **Account (security)** covers both worlds: change your crew password (other sessions are revoked), Supabase-only accounts can *set* a crew password to unlock the 🐝 tab too, and **Sign out other devices** nukes every session but yours. `/api/me` reports `has_password`/`supabase_linked`/`email` for self only. **📦 Download my data** (`GET /api/me/export`) bundles your profile, servers + roles, friends graph, owned agents (prompts included), saved bookmarks, blocks, and *your own* messages — labeled `Server #channel` / `DM: name` / `Group DM: names` — as a dated JSON attachment. Never other people's message content.

Local username/password (PBKDF2 + bearer sessions) is the default. To run login through **Supabase** instead, set `SUPABASE_URL` + `SUPABASE_ANON_KEY` in `backend/.env` (gitignored). The login card then shows an **⚡ Supabase** tab (default) next to **🐝 crew account**: the frontend signs in with `@supabase/supabase-js`, the backend verifies the access token via `/auth/v1/user`, and finds-or-creates a local user keyed on `users.supabase_uid` (matching email links pre-existing accounts). `GET /api/auth/config` exposes the public config to the page. Local accounts, bots, and seeds keep working in the crew tab.
